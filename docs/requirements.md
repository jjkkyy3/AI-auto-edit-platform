# 产品需求基线

## 范围与状态

本文件记录技术负责人在 P0-01 下发的产品背景、技术基线和架构约束。除工程文档外，功能均为待实现需求，不代表已有可运行系统。

## 产品定位

建设面向多用户的 AI 短剧自动化生产平台，支持 Windows/Linux 部署、远程 GPU 模型执行和云端 API。核心界面为白色主题、类似 n8n 的横向可视化节点画布。

主节点展示整集阶段，子节点默认折叠，点击展开；具体节点应支持参数、提示词、输出预览和日志查看。

## 业务流程

整集流程：

```text
剧本输入 → 剧本解析 → 人物资产生成及审核 → 场景资产生成及审核
→ 分镜规划及审核 → 动态分镜分流 → N 条分镜独立执行
→ 分镜汇总 → 音频字幕 → FFmpeg 合成 → 成片审核 → MP4 导出
```

每条分镜流程：

```text
输入绑定 → 首帧生图 → 图片审核 → 视频生成 → 视频审核 → 素材归档
```

## 功能要求

| ID | 需求 | 关键行为 |
| --- | --- | --- |
| REQ-01 | 项目与多用户 | 管理项目归属，隔离不同用户和项目的数据、素材及执行操作 |
| REQ-02 | 剧本输入与解析 | 将剧本解析为人物、场景、对白等结构化信息，保留输入和解析版本 |
| REQ-03 | 人物资产 | 稳定人物 ID、参考资产生成、人工审核及版本绑定，作为后续镜头标准 |
| REQ-04 | 场景资产 | 稳定场景 ID、参考资产生成、审核及版本绑定 |
| REQ-05 | 分镜规划 | 保存镜头顺序、输入绑定和规划结果，审核通过后允许进入生产 |
| REQ-06 | 动态分支 | 按实际分镜数量生成 N 条支线；逻辑并行与物理执行并发分开控制 |
| REQ-07 | 分镜执行 | 每条支线独立完成首帧、审核、视频、审核和归档 |
| REQ-08 | 审核门禁 | 待审核或驳回时阻断依赖该结果的下游，生成完成不能自动视为审核通过 |
| REQ-09 | 节点模型配置 | 每个生成节点独立选择模型、凭据引用及兼容参数，记录执行时配置 |
| REQ-10 | 统一模型接入 | 通过内部统一契约适配 ComfyUI、Ollama、自部署远程服务及云端 API |
| REQ-11 | 素材版本 | 唯一 ID 与不可变版本引用，保留提示词、模型和审核来源 |
| REQ-12 | 局部重试 | 按失败节点或指定分镜重试，保留成功结果与历史尝试，避免重复外部提交 |
| REQ-13 | 状态与恢复 | 后端持久化权威任务状态；刷新、断连或进程重启后可恢复和核实执行进度 |
| REQ-14 | 汇总与合成 | 等待全部必需分镜通过，按镜头顺序处理音频字幕并执行 FFmpeg 合成 |
| REQ-15 | 成片审核与导出 | 审核通过后导出 MP4；问题应定位到对应分镜或合成环节 |
| REQ-16 | 远程执行 | 通过 API 或 Model Agent 连接 GPU，平台不依赖模型与业务同机部署 |

## 强制架构与运行约束

1. 前端画布不直接执行流程；业务状态以后端持久化记录为准，执行引擎与 UI 解耦。
2. 人物、场景、分镜及素材采用稳定唯一 ID 与版本关系。审核针对具体版本，不能自动沿用旧版本结论。
3. 本地与云端模型采用统一内部适配接口；实际协议和能力不同，不以 API Key 是否为空判断部署位置。
4. 数据库和素材存储必须持久化，数据库保存元数据及文件引用；Redis、GPU 临时盘或模型服务历史不能成为唯一记录。
5. 不向 Git 提交 API Key、密码、真实环境配置、模型权重、生成素材或数据库数据。
6. 远程模型可通过 API 或 Agent 执行，不假设 GPU 服务器安装 Docker。
7. 生成与队列任务需要幂等、资源限制、错误记录和有限重试；结果未知时先核实外部任务。
8. 多用户访问必须执行服务端权限校验；前端不得直接持有供应商密钥。

## 技术基线

前端 React + TypeScript + Vite + React Flow + Ant Design；后端 Java 21 + Spring Boot 3.x；PostgreSQL + Flyway；Redis；Model Agent 使用 Python + FastAPI；模型服务包括 ComfyUI、Ollama 和云端 API；合成使用 FFmpeg；平台部署使用 Docker Compose；版本管理使用 GitHub。
