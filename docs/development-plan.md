# P0–P7 开发阶段计划

## 管理原则

以下阶段划分是基于当前需求提出的规划草案，后续具体任务编号、范围与验收以技术负责人下发内容为准。列入计划不代表获准执行；本次仅执行 P0-01，完成后等待下一条任务。

| 阶段 | 目标与规划范围 | 依赖 | 规划验收重点 |
| --- | --- | --- | --- |
| P0 工程基础 | P0-01 仓库检查与规范文档；后续授权后再初始化前后端、代理骨架、配置与基础检查 | 无 | 文档与实际状态一致；后续工程能独立构建，无密钥入库 |
| P1 项目与持久化基础 | 项目、用户与权限边界、PostgreSQL/Flyway、素材存储抽象和基础 API | P0 对应任务通过 | 数据持久化、迁移可重建、跨用户/项目隔离 |
| P2 工作流内核与画布 | 节点协议、运行状态机、任务分发、审核门禁、模拟执行器；白色横向可折叠画布 | P1 | 前端反映后端真实状态；待审核阻断下游；刷新及重启恢复 |
| P3 剧本与人物场景资产 | 剧本解析、结构化校验、稳定人物/场景 ID、资产工作台、版本与审核 | P2；真实生成依赖 P4 | 资产可追踪，审核绑定版本；修改不破坏历史，可先用模拟生成验收 |
| P4 模型中心与执行接入 | 节点独立模型配置、凭据引用、统一适配、ComfyUI/Ollama/云端、Model Agent | P2；关联 P3 资产契约 | 健康检查、模板参数映射、外部任务跟踪；超时核实、有限重试、日志脱敏 |
| P5 分镜生产闭环 | 分镜规划审核、动态 N 分支、首帧/视频生成与审核、归档、局部返工、资源并发限制 | P3、P4 | 一个真实分镜闭环，再验证多个分镜；单点失败不重跑其他已通过结果 |
| P6 后期合成与交付 | 汇总门禁、音频字幕、FFmpeg、成片审核、指定分镜返工、MP4 导出 | P5 | 等待必需镜头、按原顺序合成、版本可追溯，合成重试不重复生成视频 |
| P7 部署与生产验证 | Docker Compose、Windows/Linux 验证、远程执行联调、备份恢复、监控、配额与稳定性 | P6 | 多用户隔离、断连恢复、持久化恢复和端到端流程；GPU 无 Docker 场景有支持路径 |

权限、状态持久化、凭据保护与测试应随功能推进，不延后到 P7 才补。P3/P4 的接口可以在任务明确授权后协调推进，但不因此自动授予并行开发范围。

## 本次任务 P0-01

交付内容：

1. 检查当前 Git 状态、分支、远程、已有文件与目录。
2. 保留已有代码、文件、未提交内容和许可证；冲突时停止并报告。
3. 提出 Monorepo 结构，维护 README、AGENTS 和三份设计文档。
4. 创建覆盖密钥、权重、生成素材、数据库数据、构建及 IDE 文件的 `.gitignore`。
5. 对已跟踪文件做明显密钥模式与大文件检查，仅报告发现，不删除、不改写历史。
6. 验证文档链接、内容一致性、忽略规则、空白错误和最终 Git 状态。

本阶段禁止安装大量依赖、下载模型、启动 Docker、连接 GPU、实现登录/画布/模型调用/业务表、修改远程、自动推送或合并。

## 里程碑与进入条件

- 每项任务提交实际文件清单、验证命令、结果、风险和验收结论；负责人下发下一任务后再继续。
- P2 使用模拟执行器验证状态机，不能用前端状态切换冒充可恢复执行。
- P4/P5 真实联调需要对应任务明确授权并具备凭据、可用模型、网络与存储；阻塞时报告，不擅自租资源或购买 API。
- 首个端到端里程碑建议为三个分镜：人物确认、首帧和视频审核、驳回局部重做、刷新恢复、顺序合成及 MP4 导出。
- 不预设完成日期或服务器容量；依赖版本、性能目标、成本策略和运维方案在对应任务内确定并验证。
